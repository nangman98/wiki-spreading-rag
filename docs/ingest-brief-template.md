# Ingest 에이전트 브리프 템플릿

LLM 에이전트(Claude Code sub-agent 등) 한 개에 파일 목록 하나와 함께 그대로 넘긴다. `<...>`만 바꾼다.

---

목적: `<프로젝트>`의 `<날짜>` 이후 변경 문서를 위키 atomic note로 만들어, 다음 세션의 LLM이 노트 검색만으로 사실·수치·결정을 찾아 쓸 수 있게 한다.

**선행**
1. `<vault>/schema.md`(노트 형식)를 먼저 읽는다.
2. 관련 기존 노트를 찾는다: `ls <vault>/notes`, `grep -ril <키워드> <vault>/notes`. 프로젝트 허브 노트를 읽어 기존 체계를 파악한다.

**소스**
- 담당 파일 목록: `<목록 파일 경로>`. 원본은 읽기 전용, 수정 금지.
- 파일이 많으면 README·STATUS·provenance·결과 페이지의 판정 부분을 우선한다.

**작성 규칙**
- 주제로 묶는다. 소스 1:1 변환 금지. 노트 하나에 주장 하나, 300–600단어, 800 초과 시 분할.
- 같은 주제의 기존 노트가 있으면 새로 만들지 말고 그 자리에서 부분 수정한다(다른 에이전트와 동시 작업 중이므로 파일 전체 덮어쓰기 금지).
- 수치는 소스 그대로 + 단위 + 출처 경로. 창작 금지. 추론은 `?? ` 접두. 소스끼리 상충하면 양쪽을 남긴다.
- 계산 노트에는 무엇을 계산했는지(계, 원자 수, 계산 종류, 코드·설정)와 결과·판정을 담는다.
- `[[wikilink]]`는 실존 slug만 (`ls <vault>/notes/<slug>.md`로 확인).
- 소스 언어를 유지하고 기술 용어는 영어로 둔다.

**금지**
- `Index.md`, `moc-*`, 프로젝트 허브, `schema.md`, `raw/`, `archive/` 수정 (본체가 마지막에 일괄 처리)
- git 명령, 원본 파일 수정
- `<비공개 범주: 예) 특허, 미발표 협업 정보>` 기재

**반환**
1. 표: `slug | 신규/갱신 | 한 줄 내용 | 주요 소스`
2. 허브 노트·MOC에 넣을 항목 제안 (slug + 한 줄)
3. 처리 못 한 파일과 이유. `done + skipped = 담당 파일 수`
